<h3>Choose ONE option and submit ONLY ONE. Either option earns full credit for HW #3.</h3>
<p>You may do both for extra practice if you like, but only one submission is counted. Pick the one you want graded and submit that.</p>

<h4>Option A &mdash; Record a video: play and spell every perfect 4th, with a metronome</h4>
<p><strong>A METRONOME IS REQUIRED for this option, and it must be audible in your recording.</strong> Every interval has to land on a click. Any metronome works &mdash; a phone app, or the built-in metronome on the keyboards in Room 269 (see the lab hours below).</p>
<p>Record a video of yourself at the piano playing <strong>every perfect 4th as a blocked (harmonic) interval, chromatically up from middle C and back down</strong>, and <strong>saying the spelling of each one out loud as you play it</strong>. This is exactly what <a href="https://youtu.be/xg1L2ccDO9M">the perfect 4ths chromatic play-along video</a> does &mdash; the same intervals in the same order &mdash; except that you name every interval as you go, and you get more time on each one. (The whole <a href="https://www.youtube.com/playlist?list=PLnO4XsbPuZRTRSBYWxtqjlrUKX5JrdTJl">interval play-along playlist</a> is there too if you want the others for practice.)</p>
<ul>
  <li><strong>Start on C4&ndash;F4</strong> (middle C with the F above it). Go up chromatically one interval at a time: C&ndash;F, C&sharp;&ndash;F&sharp;, D&ndash;G &hellip; <strong>turn around on C5&ndash;F5</strong>, then come back down chromatically <strong>to end on C4&ndash;F4</strong>. That is <strong>25 intervals in all</strong> (13 going up, 12 coming down).</li>
  <li><strong>Play each perfect 4th as a harmonic interval</strong> &mdash; both notes together (blocked), not one after the other &mdash; and <strong>land every interval on a click</strong>.</li>
  <li><strong>The goal is four beats per interval at quarter note = 60</strong>: set the metronome to 60 and change intervals every four clicks (that is 100 seconds for the whole thing). You may go faster if you like, as long as every blocked interval falls on a click and you stay with the beat the whole way.</li>
  <li><strong>Say the spelling of every interval as you play it, spelled as a FOURTH.</strong> For example: <em>&ldquo;F to B-flat, perfect 4th.&rdquo;</em> The two letter names must be four letters apart (F&ndash;G&ndash;A&ndash;B = a 4th). &ldquo;F to A-sharp&rdquo; is <em>not</em> a perfect 4th &mdash; it is the same sound spelled as a 3rd, and it does not count. <strong>Recommended: sharps on the way up, flats on the way down</strong> (C&sharp;&ndash;F&sharp; going up, D&flat;&ndash;G&flat; coming down). Either spelling is accepted as long as the interval is correctly spelled and named as a perfect 4th (C&sharp;&ndash;F&sharp; or D&flat;&ndash;G&flat; &mdash; never D&flat;&ndash;F&sharp;). On the way down you may name the two notes in either order (&ldquo;B to E&rdquo; or &ldquo;E down to B&rdquo;).</li>
  <li><strong>Your video file must be under 2 minutes long.</strong> A file that is 2:00 or longer receives no credit. One take, no editing needed &mdash; if you stumble, stop and record again.</li>
  <li>Your hands, the keyboard, your voice and the metronome all need to be clearly on the recording. A phone propped on the music stand is fine.</li>
</ul>
<p><strong>How Option A is graded:</strong> on accuracy &mdash; all 25 intervals present in the right order, every one blocked and on a click, every one correctly spelled and named as a perfect 4th, and the file under two minutes.</p>
<p><strong>To submit Option A:</strong> use the <strong>File Upload</strong> tab below and upload the video file itself (.mp4 or .mov from a phone is fine). Do not paste a link to a cloud drive; upload the file.</p>

<h4>Option B &mdash; Play Da Capo on its PERFECT 4THS course</h4>
<p>Play Da Capo, the reading game, on its <strong>PERFECT 4THS</strong> course: <a href="https://da-capo-game.netlify.app">https://da-capo-game.netlify.app</a></p>
<p>Da Capo is a little arcade game: you are a dragon, enemies carry flashcards, and you answer a card by playing the note or interval it shows. This assignment uses one specific set of cards &mdash; perfect 4ths only, melodic first and then harmonic (two notes played together).</p>
<p><strong>Choose the right course first.</strong> A run in any other course does not count for this assignment.</p>
<ol>
  <li>On the title screen choose <strong>HOMEWORK</strong>.</li>
  <li>Select <strong>PERFECT 4THS</strong>. This starts the run directly.</li>
</ol>

<p><strong>You have full credit when EITHER of these is true:</strong></p>
<ul>
  <li>you beat all 24 stages, <em>or</em></li>
  <li>you have cleared 100 cards.</li>
</ul>
<p>Whichever comes first. The game keeps count for you: GET CODE (from the pause menu, or from the screen at the end) tells you whether you have earned credit yet and, if not, exactly how many more cards you need.</p>
<p><strong>You do not need a MIDI keyboard.</strong> The letters A to G on your computer keyboard play those notes. For a black key, tap T (sharp) or R (flat) first and the next letter plays it. When a card shows two notes stacked on top of each other, play them <em>together</em> &mdash; press both letters at the same time, the way you would on a piano. If you would rather play it on a real keyboard, the Room 269 keyboards work as MIDI controllers during lab hours (cables provided) &mdash; see below.</p>
<p><strong>You do need a laptop or a desktop computer.</strong> Da Capo has no touch controls at all, so a phone or an iPad cannot play it, with or without a keyboard. Use your own computer, the music computer lab, or anywhere you have the internet and a laptop or desktop.</p>

Use the SAME browser on the SAME computer every time; when you come back, press <strong>CONTINUE</strong> on the title screen (not START GAME, which begins a brand new run); if the game asks, choose KEEP THE SAVED RUN.</p>

HOW THE TWO GRADING PATHS COEXIST -- checked in code, not assumed
(Grading_Hub, 2026-09-15):
  - CanvasPull.decode_submissions skips any submission whose body has no
    KTS1/PTO1 prefix. A file upload has body null. So video students
    never reach the rubric, never land in no_rubric, never fail decode.
    BEFORE THIS PASS they were also invisible -- counted in "N
    submission(s)" but indistinguishable from unsubmitted rows. NOW
    CanvasPull.uploads_without_code lists them (online_upload type, or
    any attachments, and no code in the body) and both the single-pull
    status line and the batch report print them by Canvas user id. A
    student who uploads a video AND pastes a code in the same attempt is
    NOT in that list -- the code path owns them.
  - A garbled TEXT submission still goes through the decode path and
    fails loudly there ("FAILURES: N" / the fail count); it is not
    confused with an upload.
  - ExternalGrades (tab 6) posts exactly the rows in the sheet with a
    Canvas ID and a numeric TOTAL; blank grades are skipped and listed
    (SKIP_NO_GRADE), never posted as 0. It does not look at the
    assignment's existing grades or submission types at all. So the
    "assumes no KTS1 path exists" worry is moot: the module never
    assumed anything about the assignment, it only assumed the sheet is
    the whole truth for the rows it contains. NO COMPATIBILITY FIX
    NEEDED there. The one operational rule: keep code students OUT of the
    sheet (or leave their TOTAL blank), or the sheet's number overwrites
    the rubric's.
  - Both paths use the same GradePost.build_request PUT, one student at
    a time, so they cannot half-overwrite each other -- the last write
    for a given student wins, whole.

WHY THE CODE CHANGE WAS NEEDED (Grading_Hub, this pass). AssignmentSpec
read ONE submission_type string and AssignmentCreate's create/update
builders each sent ONE assignment[submission_types][]= param, so the hub
could not create a Canvas assignment accepting two types. Now: the form
may pass a submission_types Array; the spec/row carry the ordered de-
duped set AND the old single string (first entry) for every existing
reader; the builders emit one repeated param per type (Rails array
encoding, which Canvas's API documents for this field); "none"/"on paper"
refuse company. Single-type bodies are byte-identical to before -- pinned
by _test_assignment_create_multi_type_requests ("one-entry set == legacy
string, byte for byte"). UI: an "Also accept" checkbox row under the
dropdown, all off by default. 774/774 + smoke. NOT YET SENT TO REAL
CANVAS -- section 4's "open it in Canvas as a teacher" step is the live
check.
