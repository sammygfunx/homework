  - A stage = one quality in one position, 12 levels, one per key, in
    the order C G D A E B F# Db Ab Eb Bb F (scripts/game_state.gd
    get_root_for_level); level N has N chords (get_enemy_count_for_level),
    so one stage is 78 chords and Major + Minor are 156.
    "Cleared" = all 12 roots in mastered_chords
    (is_chord_type_fully_mastered; the stage card then reads
    "✓ MASTERED", scripts/stage_selection.gd:274-275, and the
    Statistics grid "12/12 ✓", scripts/stats_display.gd:136). Every
    stage is unlocked from the start (is_chord_type_unlocked returns
    true, stage_selection.gd:359-362).
  - WHY IT WAS GATED: through v51.8 the KTS1 code (scripts/
    session_report.gd score_rows) carried, per stage, only correct /
    attempted answers, plus "levels" = distinct root-position levels
    over ALL NINE qualities. So "levels 24" could be 12 major + 12
    dominant 7th, and no rubric could tell "Major Triads 12/12".
  - THE FIX, SHIPPED (pass CC-LEVELS, 2026-10-26, Chord Crush v51.9.0,
    Chord_Crush a0e8b4a + 9fbeb8f): after "levels" and "levels_all" the
    code sends one "<stage>_levels" row per started stage (played or
    cleared): attempted 12, correct = distinct levels cleared (capped at
    12). New ids only; every older row keeps its id and place. Frozen in
    Chord_Crush tests/canvas_report.gd. Grading_Hub d1b60c1 added
    rubrics/chordcrush_board2.rubric.json: four threshold columns at 12,
    maj_levels 50, min_levels 50, dim_levels 3, aug_levels 3 (max 106;
    GradePost does not cap, so 106 posts as 106). Pinned on nine real
